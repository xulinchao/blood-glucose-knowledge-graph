# TraeWork 工作流说明

TraeWork 与 Cursor 共用本仓库：**同一数据、同一真实性规则**。  
规则全文见根目录 [AGENTS.md](../AGENTS.md)「选题与内容真实性」。

| Skill | 用途 |
|-------|------|
| [.cursor/skills/blood-glucose-daily-brief/SKILL.md](../.cursor/skills/blood-glucose-daily-brief/SKILL.md) | **查今日精选**（默认入口，AIHOT 式） |
| [.cursor/skills/blood-glucose-topic-authenticity/SKILL.md](../.cursor/skills/blood-glucose-topic-authenticity/SKILL.md) | 写稿 / 真实性 / 对抗性审核 |

维护者**非执业医生** — TraeWork 生成的一切文案均须遵守对抗性审核与口播底线。

## 三条流水线

```
┌─────────────────────────────────────────────────────────────┐
│  任务 A：每日采集（无需 LLM，Windows 计划任务 / TraeWork）      │
│  scripts/run-daily-harvest.bat                                │
│    → data/exports/daily-harvest-YYYY-MM-DD.json   （全量）     │
│    → data/exports/daily-brief-YYYY-MM-DD.json     （精选）     │
│    → research-daily/YYYY-MM-DD-采集日报.html                  │
│    → research-daily/YYYY-MM-DD-精选日报.html    ★ Agent 默认读  │
│    → data/discovered-topics.json（仅 gate.passed + topic_pick） │
└─────────────────────────────────────────────────────────────┘
                              ↓ claim_gate 已内置于采集
┌─────────────────────────────────────────────────────────────┐
│  Risk Gate — src/claim_gate.py（规则主张拆解 + 可写性否决）     │
│  heat_score 仅传播 · writability_score / gate.passed 决定可写稿   │
└─────────────────────────────────────────────────────────────┘
                              ↓ Agent 默认读精选 JSON
┌─────────────────────────────────────────────────────────────┐
│  精选层 Schema 2.0 — curate_daily_brief.py                     │
│  时间线按 gate.passed 排序 · 三段式字段 · 理由链 agent_hints      │
│  指针：data/exports/latest-brief.json                         │
└─────────────────────────────────────────────────────────────┘
                              ↓ 可选，需 LLM
┌─────────────────────────────────────────────────────────────┐
│  任务 B：监控日报（TraeWork Agent，可选）                       │
│  输入：精选 JSON + harvest JSON + 权威来源核实                  │
│  输出：research-daily/YYYY-MM-DD-日报.html                    │
│  侧重：政策/指南核实、Top2 口播建议、待核实清单                 │
└─────────────────────────────────────────────────────────────┘
```

| | 采集日报 | **精选日报** | 监控日报 |
|---|----------|--------------|----------|
| 谁生成 | Python | Python（`curate_daily_brief`） | TraeWork Agent |
| **展示（HTML）** | `research-daily/*-采集日报.html` | `research-daily/*-精选日报.html` | `research-daily/*-日报.html` |
| **文档（MD）** | `research-daily/*-采集日报.md`（Agent 用） | `research-daily/*-精选日报.md`（Agent 用） | **`content/research-daily/*-日报.md`**（Quartz 笔记，不在 research-daily 放 MD） |
| 条数 | 全量（100+） | 精选（~12 时间线） | 人工解读 2–4 热点 |
| Agent 默认 | 否 | **是** | 仅「要核实版」时读 HTML |
| 可否当医学结论 | 否 | 否（含 hook 分区） | 仅核实后可写「已核实」 |
| gate/tier 来源 | `claim_gate.py` 计算 | 沿用采集结果 | **只读不算**，禁止自评 |
| 新选题查重 | — | — | **必须**，见 v2 规则 |

## TraeWork Agent 任务提示词（监控日报 v2）

> v2 变化：① 严禁自评 gate/tier，只读精选 JSON 已算好的值；② 提「新选题」前必须与现有155条选题查重；③ 输出可直接合并的 JSON patch；④ 增加选题积压提醒与学习笔记候选，衔接后续写稿/学习笔记流程。

```markdown
# 角色
你是血糖/控糖科普编辑，非医生。工作目录为本仓库根目录。

# 必读
1. AGENTS.md「选题与内容真实性」
2. .cursor/skills/blood-glucose-daily-brief/SKILL.md（先读精选）
3. 当日 data/exports/daily-brief-YYYY-MM-DD.json
4. 需要细节时再读 data/exports/daily-harvest-YYYY-MM-DD.json
5. data/discovered-topics.json（topics + archive 两个数组，用于选题查重）

# 任务
基于**精选日报**产出两份监控日报（不要重复跑采集，不要手写/编造 gate 或 evidence_tier）：

1. **展示用 HTML**（唯一放在 research-daily）
   `research-daily/YYYY-MM-DD-日报.html`
   首行保留 `<!-- Generated by Trae Work -->`

2. **文档用 Markdown**（发 Quartz 笔记）
   `content/research-daily/YYYY-MM-DD-日报.md`
   带 YAML frontmatter（title / date / tags），正文与 HTML 同内容、可略精简
   **不要**在 `research-daily/` 下再写 `*-日报.md`

# 真实性铁律（比精选日报更严，必做）
对每条要写入日报的主张：
- 问：若作者只想骗点击，这条标题在暗示什么？
- **`gate.passed=false` 的条目禁止进入「今日热点」/「可转化选题」，只能出现在「待核实清单」**
- **禁止自己填写或推断 `gate_passed` / `evidence_tier`** —— 只能读精选 JSON 里 `claim_gate.py` 已算出的值；某条目在精选 JSON 中查不到 gate 结果时，直接标「未过 Gate 核实，不建议采用」，不要凭印象打分
- evidence_tier 分级：
  - A/B → 可 `cite_directly`，必须附原链接
  - C → 只能 `verify_before_script`，标注「数字待与指南对照」
  - D/E 或 `use_as=hook_only` → 只写「网友/UP主在讨论 X」，不得写成事实
- 政策/指南动态只信白名单来源：nhc.gov.cn、who.int、dxy 系、期刊；非白名单来源一律标「民间说法，未见官方信源」
- 禁止：根治、保证逆转、替医嘱用药

# 选题查重（写「可转化选题」前必做，避免与现有155条选题库撞车）
- 读 `data/discovered-topics.json` 的 `topics` + `archive` 两个数组的全部标题
- 拟提出的每条新选题，先做标题关键词比对；核心关键词与已有任意一条重合，视为重复
- 命中重复 → 不得作为「新选题」提出，只标「与已有 {disc-id} 类似，建议关联/合并」，附对应 id
- 统计当前 `topics` 数组中 `script_status=pending` 的条数：若 ≥ 20，日报最上方加一行「⚠️ 选题积压 N 条，建议优先清理已有选题，本期暂缓新增」

# 结构
1. 今日热点（2–4 条，仅 `gate.passed=true`，附来源链接与 evidence_tier badge）
2. 趋势观察（可引用 cross_platform）
3. 政策/指南动态（仅白名单来源，可补充检索）
4. 可转化口播选题 Top 2（仅 writable_picks 且已查重；每条含 why_selected / misleading_risk / safe_rewrite / dedup_check_result，并附一段可合并进 discovered-topics.json 的 JSON patch，见下方格式）
5. 学习笔记候选（从今日 A/B 级、`gate.passed=true` 的条目中挑 1-2 条「知识本身」值得展开的，标「建议写学习笔记」，供后续学习笔记流程使用，不是选题角度而是知识点本身）
6. 待核实清单（合并 `agent_hints.verify_list` + gate 未过项 + 你未完成的 fact-check）
7. 选题积压提醒（触发阈值时才出现，见上）

# 「可转化选题」JSON patch 格式（第4项每条都要附）
不要自己编 `disc-XXX` 编号（编号由采集脚本统一分配，人工编号容易和已有选题冲突）；
`id` 留空，标题作为唯一性判断依据，实际入库仍需跑一次采集脚本或由维护者手动分配 id。

\`\`\`json
{
  "id": null,
  "title": "选题标题",
  "angle": "切入角度",
  "category": "辟谣纠偏|饮食指南|数字科普|实操方法|症状预警|工具测评|案例故事|避坑指南",
  "source_urls": ["原始链接"],
  "discovered_date": "YYYY-MM-DD",
  "harvest_meta": {
    "evidence_tier": "A|B|C|D|E（须来自精选JSON，不得自评）",
    "use_as": "cite_directly|verify_before_script|hook_only",
    "creator_note": "写稿前须核实的点"
  },
  "why_selected": "为什么选它",
  "misleading_risk": "可能被误读成什么",
  "safe_rewrite": "更安全的表达方式",
  "dedup_check_result": "未命中已有选题 | 与 disc-XXX 类似，建议关联"
}
\`\`\`

# 口播底线（摘要或选题区须出现）
个体情况请咨询医生，不构成医疗建议。
```

## 常见问题

**Q：Agent 该读采集还是精选？**  
A：**默认精选**（`latest-brief.json`）。只有用户要「全部条目」才读 harvest 全量。

**Q：TraeWork 还要自己搜一遍吗？**  
A：监控日报在精选基础上**解读与核实**即可；缺 A/B 来源时再 Agent Reach。

**Q：采集失败？**  
A：看采集日报「采集异常」；常见为 OpenCLI 未连接、未登录小红书/X。

**Q：和 Cursor 会冲突吗？**  
A：不会。共用 `discovered-topics.json`；写稿相关的选题（`topics` 数组内）通过标题去重，监控日报新提的选题也须按 v2 规则先做标题查重再提出。
